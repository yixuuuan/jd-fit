# jd-fit

**给转行求职者的 JD 分析与简历改写 skill。**
A Claude skill for career switchers: screen a job description, decode the role, and rebuild your résumé as an evidence chain.

---

## 它解决什么问题

大多数求职工具做的是"让简历向 JD 靠拢"：抽关键词，塞进经历。
对同行跳槽有效。对转行者有害。

转行者真正的问题是：
**招聘方凭什么相信，一个路径不同的人能做好这份工作。**

jd-fit 只回答这一个问题。

---

## 三个阶段

```
阶段 0  硬门槛筛选   能不能投？         A / B / C 评级
阶段 1  岗位拆解     这个岗位实际干什么？ 动词层级 + 名词解释
阶段 2  证据链改写   简历怎么改？        匹配矩阵 + 经历重构 + 压力测试
```

**阶段 0：硬门槛封顶**
基本要求里 1 项缺失，最高只能评 B。2 项缺失，强制 C。
加分项再像，也不能突破。C 级默认在这里停下，不浪费时间改一份投不进去的简历。

**阶段 1：动词层级**
一条 JD 由名词和动词组成。名词（液冷、UPS、PUE）看起来吓人，但可以学。
动词才决定你每天干什么：

| 动词 | 实际要求 |
|---|---|
| 负责设计、计算、选型 | 亲手做技术工作 |
| 主导、负责、管理 | 对结果负责 |
| 协调、推动、对接 | 让别人完成 |
| 熟悉、了解 | 听得懂，能对话 |

大多数让人看不懂的 JD，名词密度高，动词其实是管理。

**阶段 2：证据链**
岗位要解决的问题 → 你解决过的问题 → 简历里的证据 → 面试能讲的故事。
不虚构。参与≠负责，协助≠主导，了解≠精通。

---

## 两种模式

| 模式 | 什么时候用 | 跑哪些阶段 | 产出 |
|---|---|---|---|
| 原型模式 | 一类岗位第一次分析 | 0 → 1 → 2 全套 | 一版主简历 |
| 单岗模式 | 该类岗位已有主简历 | 0 + 1 精简版 | 主简历上改 3–5 条，约 800 字 |

建议先把目标岗位归成 2–4 个原型。每个原型跑一次全套。
之后遇到具体岗位，只跑单岗模式。

## 安装

**Claude Code**

```bash
git clone https://github.com/yixuuuan/jd-fit.git ~/.claude/skills/jd-fit
```

**claude.ai / Claude 桌面端**

下载本仓库为 zip，在设置里的 Skills 区域上传。

**其他支持 SKILL.md 的 agent（如 Cursor）**

把 `SKILL.md` 放进对应的 skills 目录。

---

## 用法

```
用 jd-fit，原型模式：
<粘贴 JD 或链接>
<附上简历>
```

```
用 jd-fit，单岗模式，原型是「数据中心建设 PM」：
<粘贴 JD>
```

每次分析结尾会输出一行投递记录，可以直接贴进 Obsidian 或表格：

```
日期 | 公司 | 岗位 | 原型 | 评级 | 决定
```

示例输出见 [`examples/`](examples/)。

## 设计来源

- 证据链与"不虚构"原则：来自作者自用的 JD 深度分析与简历改写提示词
- 硬门槛封顶规则：参考 [sharzoy/auto-job-apply](https://github.com/sharzoy/auto-job-apply) 的 A/B/C 评分设计
